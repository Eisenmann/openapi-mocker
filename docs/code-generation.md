# Code generation

OpenAPI Mocker can turn the active contract of a project into code. Generation
is available in the full server (the **Codegen** tab and the REST API). It is
not part of the headless `openapi-mocker serve` mode.

## Languages

The **Codegen** tab and `POST /api/projects/{id}/codegen/agent` generate a
server skeleton, a client and a project file for each language you select:

| Language | `languages` value | Generated project files |
|---|---|---|
| Go | `go` | server, client, `go.mod` |
| TypeScript | `typescript` | server, client, `package.json`, `tsconfig.json` |
| Python | `python` | server, client, `requirements.txt`, `README.md` |
| Java | `java` | server interface, router, client, `pom.xml` |
| Rust | `rust` | server interface, router, client, `Cargo.toml` |
| C# | `csharp` | server interface, router, client, `.csproj`, `README.md` |

The server part is an interface with one method per contract operation, a
router, a stub implementation that answers "not implemented", and an entry
point. The client has a method per operation. Treat the output as a starting
point: review it, and compile it in your own toolchain, before you rely on it.

```bash
curl -X POST http://localhost:8080/api/projects/<projectId>/codegen/agent \
  -H 'Content-Type: application/json' \
  -d '{"languages":["go","typescript","python"],"project_name":"shop"}' \
  -o codegen.zip
```

The answer is a zip with one folder per language and a `manifest.json` that
lists the files, the strategy used for each language and any warnings. If some
languages fail, the ones that worked are still returned and the error is in
the manifest.

## Strategies

Each language is generated by one of three strategies. The default is `native`
for all six languages above. Send `"strategy"` in the request to ask for
another one:

- `native`: built-in generators, no external tools needed.
- `openapi`: runs [openapi-generator-cli](https://openapi-generator.tech/) for
  the language. Java and the CLI jar must be available to the server; set the
  jar path with `OPENAPI_GENERATOR_CLI` (default `openapi-generator-cli.jar`
  in the working directory). The same adapter is the fallback for a language
  that has no native generator.
- `cicd`: instead of code, returns a GitHub Actions workflow that runs
  openapi-generator-cli in your pipeline.

## Go only: the original downloads

`GET /api/projects/{id}/codegen/server` and `GET /api/projects/{id}/codegen/client`
(the two buttons under the multi-language card) download a Go server or a Go
client as a zip, with no setup.
